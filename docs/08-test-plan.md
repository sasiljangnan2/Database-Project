# 테스트 및 시연 계획

현재 자동 테스트는 홈·프로세스 health만 제공한다. 아래 항목은 업무 구현 시 추가할 인수 기준이다.
무결성과 잠금 검증은 SQLite 대체 없이 MySQL에서 수행한다.

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| T01 | 이메일 중복·role 주입·타인 예약 조회 | 가입 거절·권한 상승 차단·404 |
| T02 | A→B가 점유된 동일 좌석으로 B→C 요청 | 연속 판매 성공 |
| T03 | A→C와 B→C를 서로 다른 DB 연결로 동시 요청 | 한 요청만 성공, 다른 요청 409 |
| T04 | A→B는 좌석1, B→C는 좌석2 점유 후 A→C 조회 | 구간 전체 가능 좌석 0 |
| T05 | 좌석 여러 개 중 하나 충돌 | 예약·승차권 전체 rollback |
| T06 | 결제기한 직전·정각·직후와 만료 정리 경합 | 정각부터 결제 불가, 좌석 재판매 가능 |
| T07 | 결제 같은 키·같은 본문 동시 재전송 | 성공 결제 1건, 승차권 발권 1회 |
| T08 | 결제 같은 키·다른 본문 | 409, 기록 추가 없음 |
| T09 | 결제 실패 후 새 키 재시도 | 기한 내 성공 가능 |
| T10 | 2장 중 1장 취소 및 환불 실패 | 부분취소, 좌석 해제, 환불 FAILED |
| T11 | 실패 환불 재시도·취소 중복·총액 초과 | 중복 지급 없음, 초과 금액 거절 |
| T12 | 취소와 탑승 확인 동시 요청 | 하나의 유효 상태 전이만 성공 |
| T13 | 운임 변경 전 예약 결제 | 기존 확정금액 유지 |
| T14 | 자정 이후 중간역 승차일 검색 | 편성 시작일이 아닌 승차역 날짜로 검색 |
| T15 | 다른 운행 정차·다른 열차 좌석 조합 | 예약 생성 거절 |
| T16 | 동일 열차의 겹치는 운행 동시 등록 | 하나만 성공 |
| T17 | 운행 취소와 예약·결제 동시 실행 | 취소 후 새 발권 없음, 환불 요청 일관성 |
| T18 | 로그아웃한 토큰 재사용·일반회원 관리자 API | 401·403 |

동시성 테스트는 연결 2개와 barrier를 사용해 실제 동시 요청을 만들고 최종 DB 상태도 검사한다.
시스템 시간은 주입 가능한 clock으로 고정한다. 성공 응답만 검사하지 않는다.
시연: 회원가입 → 날짜 검색 → 2좌석 예약 → 결제 → 발권 조회 → 1장 취소·환불 → 나머지 탑승 확인.
별도 시연으로 연속 구간 재판매, 좌석 충돌, 만료, 중복 결제를 확인한다.
