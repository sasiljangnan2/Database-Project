# 업무 규칙 및 상태 전이

## 좌석 구간과 예약

승차 순서 b, 하차 순서 a는 b < a여야 한다. 구간은 [b, a)로 취급한다.
기존 구간 [x, y)와 신규 구간 [b, a)는 x < a AND b < y일 때 겹친다.
A→B와 B→C는 같은 좌석에 연속 판매할 수 있다.
다만 요청 구간 전체에서 같은 좌석이 비어 있어야 한다. 구간별 잔여 수의 최솟값으로 계산하지 않는다.

예약 순서:

1. 인증한 회원 ID를 사용한다. 요청으로 user_id를 받지 않는다.
2. train 행을 잠그고 해당 run을 재조회한다. 판매중, 운영중, 승차역 출발 전인지 확인한다.
3. 같은 운행의 정차이며 순서가 올바른지, 인원 1~9명과 중복 없는 좌석 수가 같은지 확인한다.
4. 모든 좌석이 운행 열차 소속이고 등급별 운임이 있는지 확인한다.
5. 동일 열차의 기한 지난 결제대기 예약을 잠금 안에서 만료 처리한다.
6. HELD이면서 기한이 남은 승차권과 ISSUED/BOARDED 승차권의 겹침을 조회한다.
7. 하나라도 충돌하면 전체 rollback 후 409 SEAT_CONFLICT를 반환한다.
8. 예약·좌석별 HELD 승차권·확정금액을 함께 저장한다. 일부 좌석만 성공시키지 않는다.

제안 기한: 생성 후 10분과 승차역 출발시각 중 빠른 시각.
now >= expires_at이면 만료다. 검색은 만료된 HELD를 제외하고,
예약·결제 등 쓰기는 잠금 후 만료를 확정한다. 정리 작업은 별도 서비스로 주기 실행하도록 추후 구현한다.

## 상태

| 대상 | 허용 전이 |
| --- | --- |
| 예약 | PENDING_PAYMENT → PAID / CANCELLED / EXPIRED |
| 예약 | PAID → PARTIALLY_CANCELLED / CANCELLED |
| 예약 | PARTIALLY_CANCELLED → CANCELLED |
| 승차권 | HELD → ISSUED / CANCELLED / EXPIRED |
| 승차권 | ISSUED → BOARDED / CANCELLED |
| 결제시도 | 처리 결과로 SUCCEEDED 또는 FAILED 저장, 결과 변경 금지 |
| 환불 | PENDING → SUCCEEDED / FAILED, FAILED → PENDING(관리자 재시도) |
| 운행 | ON_SALE ↔ CLOSED, ON_SALE/CLOSED → CANCELLED |

예약 부분취소 여부는 취소 승차권 수로 계산한다. 모든 승차권이 취소되면 CANCELLED,
일부 취소면 PARTIALLY_CANCELLED, 그 외 결제된 예약은 PAID다.
탑승완료는 승차권 상태로 관리하며 예약에 별도 COMPLETED를 두지 않는다.

## 결제와 멱등성

실제 PG·카드정보 없이 성공/실패를 시연한다. 결제는 같은 잠금 순서로 예약 상태·기한을 재검증한다.
성공 결제 레코드, 모든 HELD 승차권의 발권과 issued_at, 예약 PAID는 한 트랜잭션이다.
실패 결제는 시도 기록만 저장하고 유효 기한 내 HELD를 유지한다.
금액은 승차권 확정금액 합계와 일치해야 한다. 성공 결제는 예약당 한 번이다.

결제 요청에는 Idempotency-Key가 필수다(1~64자). DB에서 (reservation_id, idempotency_key)를 UNIQUE 처리한다.
같은 키·같은 본문이면 기존 결제 결과를 반환하며, 다른 본문이면 409 IDEMPOTENCY_CONFLICT다.
이를 위해 정규화한 요청 본문의 SHA-256을 request_hash에 저장한다.
실패 결제 후 실제 재시도는 새 키를 사용한다. 반환은 신규 결제시도 201, 기존 재전송 200이다.

## 취소와 환불

미결제 예약 전체 취소는 예약과 HELD 승차권을 CANCELLED로 바꾸고 환불을 만들지 않는다.
발권 후에는 본인 승차권 단위 취소이며 제안 정책은 승차역 출발 전·탑승 확인 전 100% 환불이다.
수수료 정책은 원문에서 확정되지 않았으므로 별도 정책 변경 PR 없이 추가하지 않는다.
대상 승차권을 모두 검증한 다음 CANCELLED와 환불 PENDING을 한 트랜잭션으로 기록하고 좌석을 해제한다.
환불의 시연 처리 결과는 별도 트랜잭션으로 기록한다. 실패해도 승차권은 CANCELLED를 유지한다.
승차권당 환불은 하나만 만들고 실패 재시도는 기존 환불을 갱신한다.
누적 SUCCEEDED와 PENDING 환불 합계는 성공 결제금액 이하여야 하며, 재시도 때도 잠금 후 다시 검증한다.
취소 재전송은 동일 대상이 이미 취소된 경우 기존 결과를 반환하고 환불을 추가하지 않는다.
타인·다른 예약의 승차권이 섞인 요청은 전체 거절한다.

운행 취소는 신규 예약을 즉시 막고 train 잠금 안에서 영향을 받는 예약·승차권을 처리한다.
미결제는 취소, 발권 미탑승은 취소+전액 환불 요청을 만들고 reason=RUN_CANCELLED로 구분한다.
이미 탑승 확인된 승차권이 있는 운행은 MVP에서 취소를 거절하고 수동 운영 대상으로 남긴다.
시연 규모에서는 전체 취소를 하나의 트랜잭션으로 처리하며 대량 배치는 범위 밖이다.

## 운행과 탑승

동일 열차의 첫 출발~마지막 도착을 반개구간으로 비교해 겹치는 운행 배정을 막는다.
중간역 도착 <= 출발, 앞역 출발 < 다음역 도착을 확인하고 자정 이후 날짜를 증가시킨다.
판매 종료는 신규 예약만 막으며 유효한 기존 결제대기는 기한까지 결제 가능하다.
관리자만 탑승 확인한다. 운행이 CANCELLED가 아니고 상태가 ISSUED인 승차권만 가능하다.
boarding_checks.ticket_id UNIQUE와 같은 트랜잭션의 BOARDED 전이로 중복 확인을 막는다.
중복 탑승 확인은 409 ALREADY_BOARDED다. 확인 시간 제한은 원문에 없으므로 별도 도입하지 않는다.
