# 요구사항 및 역할

## 범위

회원용 예약 화면과 관리자 운영 화면을 제공한다. 직통 편도 운행과 한 예약의 동일 운행·구간 여러 좌석을 지원한다.
환승, 왕복 묶음, 실결제, 할인·마일리지, 문자 발송은 이번 범위에 넣지 않는다.
일정 변경은 취소 후 재예약이다. 원문에 없는 세부 정책은 10-decisions.md의 제안값이다.

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| F01 | 회원가입·로그인·로그아웃·본인 정보 수정 | 이메일 중복 차단, 비밀번호 해시, 일반회원 기본값, 타인 정보 차단 |
| F02 | 역·노선·열차·좌석 관리 | 식별자·정차순서 중복 차단, 사용 중인 데이터 삭제 금지 |
| F03 | 운행·시간표·운임 관리 | 순서에 맞는 일시, 동일 열차 시간 겹침 방지, 음수 운임 차단 |
| F04 | 직통 운행 검색 | 승차역의 출발일·출발시각 기준, 판매 가능 상태, 구간별 잔여 좌석 |
| F05 | 예약 및 결제대기 | 인원수와 좌석수 일치, 동일 운행·구간, 동시 중복 예약 차단 |
| F06 | 시연용 결제·발권 | 서버 확정금액 합계, 유효 기한, 중복 성공 결제·발권 차단 |
| F07 | 내역 조회 | 본인 예약·승차권·결제·환불과 취소·만료 내역 포함 |
| F08 | 예약 만료·취소 | 좌석 해제, 미결제는 환불 생성 없음 |
| F09 | 승차권 부분취소·환불 | 취소와 환불 상태 분리, 중복·초과 환불 차단 |
| F10 | 관리자 탑승 확인 | 유효 발권권만 허용, 승차권당 1회 |
| F11 | 운영 현황 | 운행일·운행편명·예약번호 필터, 미처리 환불 표시 |

## 팀원 역할 — 원문 기준

| 팀원 | 역할 | 우선 작업 |
| --- | --- | --- |
| 김준휘 | DB 설계 및 통합 테스트 | ERD·DDL·제약조건·동시성·시연 데이터 |
| 김소연 | 프론트엔드 | 가입·로그인·검색·좌석·내역·관리자 화면 |
| 김용우 | 백엔드 회원·운행 조회 | FastAPI 인증·권한·기준정보·운행·검색·운임 |
| 김준하 | 백엔드 예약·결제 | 예약·중복 방지·결제·발권·취소·환불·탑승 |

한 기능의 API·DB 계약을 먼저 합의하고 담당자가 구현한다. 다른 담당 영역 수정은 PR에서 해당 담당자에게 리뷰 요청한다.
